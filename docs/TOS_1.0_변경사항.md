# TOS_RigTools 1.0 변경 사항 (2026-11-18)

MTOS_RigTools 1.0 (`docs\MTOS_1.0_변경사항.md`) 을 바탕으로 TOS 프로젝트용으로 만든 판. 아래에 적은 것 말고는 MTOS 와 같습니다 (4. 세컨더리 본 · 5. 스킨 · 6. 리그 체크 · 7. 리깅 완료 · 0. 작업 시간 · 1. 모델링 체크, 그 데이터 포함).

## 이름 (MTOS·GE 와 같이 켜기)
- 메뉴 **TOS > TOS_RigTools** (macroScript `TOS_RigTools`, category "TOS"). MTOS 메뉴와 따로.
- Max 시작 스크립트 `TOS_RigTools.ms` · `TOS_RigToolsStd.ms`, 데이터 폴더 `scripts\TOS_RigTools\`, 설정 `plugcfg\TOS_RigTools.ini`, 다시 읽은 데이터 `plugcfg\TOS_RigTools_ref\`, 백업 `%USERPROFILE%\tos_rig_backup\`.
- 전역 이름을 모두 바꿈 (257개): `RigTools*` → `TosRig*`, `rts_*` → `trts_*`, `sbg_*`/`SBG_*` → `tsbg_*`/`TSBG_*`, `RomCheck*` → `TosRomCheck*`, `MTOS_*`/`mtos*` → `TOS_*`/`tos*`. 노드·레이어 이름 같은 문자열(`sbg_debug`, `sbg_Head` 등)은 그대로.
  → MTOS_RigTools·GE 리그 툴(같은 이름 `RigTools`·`rts_*` 를 씀)과 한 Max 에 같이 읽혀도 서로 덮어쓰지 않음. 시험: MTOS 가 설치된 Max 에서 TOS 를 읽은 뒤 `RigTools.sbgDir()` = MTOS 폴더, `TosRig.sbgDir()` = TOS 폴더, 메뉴 MTOS·TOS 둘 다 있음.
- `BipFit` · `BipConvert` · `WeightToolPos` · Max Bridge · VirusGuard · 블렌더 애드온 · Claude Max 환경은 MTOS 와 같은 파일 (두 설치기가 같은 파일을 넣음).
- 설치기 `tos_setup.ps1`: MTOS·GE 리그 툴 파일(`MTOS_RigTools*.ms`, `RigTools*.ms`, `FaceTools.ms`)은 치우지도·묻지도 않음. 나머지 설치 방식(부품 A·B·C, 백업·되돌리기, 점검, manifest)은 MTOS 와 같음.
  - 주의: MTOS 설치기는 그대로라 MTOS 를 다시 설치하면 `TOS_RigTools*.ms` 를 "이름이 비슷함" 으로 보고 치울지 물음 → N.

## 레퍼런스 폴더
- 기준 = 각 PC 의 `<루트>\ani\Character\PC` (예: `E:\TOS\ani\Character\PC`), 그 아래 직업별 폴더 `Ver5_Archer_f` · `Ver5_Archer_m` · `Ver5_Cleric_*` · `Ver5_Mage_*` · `Ver5_Warrior_*` (각 `costume\<코스튬>\<직업>_<성별>_<코스튬>_set.max`).
- 코드에는 `ani\Character\PC` 상대 경로만. 찾는 순서는 MTOS 와 같음: ini 에 저장된 경로 → 지금 Max 파일 위치에서 위로 → 드라이브마다 `X:\ani\...`, `X:\<폴더>\ani\...` → 창 [경로 변경].
- 폴더 확인: 그 안에 `*_m` / `*_f` 폴더가 있어야 함.

## 2. Biped 자동 생성 = 직업_성별 레퍼런스 그대로
- 데이터: `tos_bip_ref.ms` + `tos_bip_<직업>_<성별>.fig` 8개 (archer·cleric·mage·warrior × m·f). 각 직업 폴더의 `6th_greenschool` 코스튬(8개 폴더에 모두 있음)에서 읽음, 없으면 Biped 가 있는 첫 `_set.max`.

- 성별: MTOS 와 같음(이름의 `_m`/`_f`) + 파일 위치의 `Ver5_*_m` / `Ver5_*_f` 폴더 + 창 [성별] 칸.
